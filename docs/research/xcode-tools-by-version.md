## Summary for the tools profile

Same in all twelve builds (27A9275 differs from 27A266a only in its version strings, 27B52 from 27A9275 only in its version strings and CoreUI version, 17A400 from 17C52 only in its version strings, CoreUI version and the newest document ibtool accepts, 17B55 from 17C52 in the same three, 17B100 from 17B55 only in its version strings and the newest document ibtool accepts, 17C529 from 17C52 only in its version strings and the newest document ibtool accepts, 17E192 from 17C529 only in its version strings, its CoreUI version and CAR header strings, the newest document ibtool accepts, and the tint colour baked into the view nib of plain views, 17E202 from 17E192 only in its version strings and the newest document ibtool accepts, 17F42 from 17E202 only in its version strings, its CoreUI version and CAR header strings, and the newest document ibtool accepts, and 17F113 from 17F42 only in its version strings, the SDK build it ships and the newest document ibtool accepts, listed below): every `assetutil --info` rendition field of the Parity catalog and of a single-size AppIcon catalog,
the app-icon partial Info.plist, the app-icon PNG bytes, copypng's behaviour on all 40 case/option combinations,
the `Info.plist` and `UIViewController-*.nib` of every storyboard in the corpus, and the `actool`/`ibtool`
log output (empty bar the result paths).

Different (one row per profile field below): the version numbers, the CAR header strings and CoreUI version, three nib
encodings (a key, a default colour, a double precision), font-dictionary uniquing in two cases, and the highest
document capability ibtool accepts.
