# Asset and storyboard tools by Xcode version (27A266a, 27A9275, 27B52, 17C52, 17A400, 17B55 and 17B100)

Measured black-box on the Mac, 2026-10-17: the tools were run and their outputs read (`--version`, `assetutil --info`,
`plutil`, `nib dump` of xless's own reader, exit codes and messages). Nothing was disassembled. The seven Xcodes (27A9275 was measured on 2026-11-12, the same way, from `Xcode_27.1.xip`, 27B52 on 2026-11-12 from `Xcode_27.2.xip`, 17A400 on 2026-11-12 from `Xcode_26.0.1_Universal.xip`, 17B55 on 2026-11-12 from `Xcode_26.1_Universal.xip`, and 17B100 on 2026-11-12 from `Xcode_26.1.1_Universal.xip`):

Setup note: Xcode 26.2's actool and ibtool refuse to run without an iOS simulator runtime
(`error: iOS 26.2 Platform Not Installed.`). `xcodebuild -downloadPlatform iOS -buildVersion 26.2` answered
`iOS 26.2 is not available for download.`; the same command without `-buildVersion`, under 26.2's `DEVELOPER_DIR`, installed
iOS 26.3.1 (23D8133), and actool and ibtool 26.2 accept it. Xcode 27.1 (27A9275) needed no download: the installed iOS 27.0 runtime was enough. Xcode 27.2 (27B52) ran with it too, but its ibtool wrote SF Symbol images in another form until the iOS 27.2 runtime was installed (`xcodebuild -downloadPlatform iOS` under its `DEVELOPER_DIR`; two runtimes, 24B8117 and 24B91016s, appeared in `xcrun simctl list runtimes`); see the note after the ibtool table. The 27B52 goldens were recorded with it installed.
Xcode 26.0.1 (17A400): its actool and ibtool refuse iOS 26.3.1 (`error: No simulator runtime version from ["22F77", "23D8133", "24A434"] available to use with iphonesimulator SDK version 23A339`), and `xcodebuild -downloadPlatform iOS -buildVersion 26.0`, `26.0.1` and `23A339` each answered `… is not available for download.`. The same command without `-buildVersion`, under 26.0.1's `DEVELOPER_DIR`, installed iOS 26.0.1 (23A8464, 8.05 GB), which actool and ibtool accept; the 17A400 goldens were recorded with it. (`xcodebuild` of a device build, as for `BuildMachineOSBuild`, also wants it: `iOS 26.0 is not installed` without.)
Xcode 26.1 (17B55): `xcodebuild -downloadPlatform iOS -buildVersion 26.1` answered `iOS 26.1 is not available for download.`, as it did for 26.2 and 26.0.1. The same command without `-buildVersion`, under 26.1's `DEVELOPER_DIR`, installed iOS 26.1 (23B86), which actool and ibtool accept; the 17B55 goldens were recorded with it, and `xcodebuild` of the HelloPIF device build (for `BuildMachineOSBuild`) works with it. The 17B55 column's CoreUI-971.6 and CoreThemeDefinition-653.2 rows were measured with that runtime; its car header also says "via AssetCatalogSimulatorAgent".
Xcode 26.1.1 (17B100): the same as 26.1. `xcodebuild -downloadPlatform iOS -buildVersion 26.1` and `-buildVersion 26.1.1` each answered `… is not available for download.`; the same command without `-buildVersion`, under 26.1.1's `DEVELOPER_DIR`, installed iOS 26.1 (23B86) again, and the 17B100 goldens were recorded with it. Until it was installed, `scripts/ib-golden.sh` stopped at `error: iOS 26.1 Platform Not Installed.` although iOS 18.5, 26.0.1, 26.3.1 and 27.0 were installed (a first `scripts/assetkit-golden.sh` run, made while `xcrun simctl list runtimes` showed an iOS 26.1 (23B86) entry that `xcrun simctl runtime list` did not, wrote a Parity file equal to the one recorded after the download). `xcodebuild` of the HelloPIF device build (for `BuildMachineOSBuild`, 26B123) works with it. The 17B100 column's CoreUI-971.6 and CoreThemeDefinition-653.2 rows were measured with that runtime and equal 26.1's.
The 17A400 column's CoreUI-970.1 and CoreThemeDefinition-652 rows were measured with the iOS 26.0.1 runtime (23A8464), whose car header also says "via AssetCatalogSimulatorAgent". The 17C52 column's CoreUI-973.1 and CoreThemeDefinition-653.3 rows were measured with the iOS 26.3.1 runtime (23D8133): the car header says "via AssetCatalogSimulatorAgent", so those strings likely come from the installed runtime, not from Xcode 26.2 itself. 27A266a needs only its own iOS 27.0 runtime.

## Summary for the tools profile

Same in all seven builds (27A9275 differs from 27A266a only in its version strings, 27B52 from 27A9275 only in its version strings and CoreUI version, 17A400 from 17C52 only in its version strings, CoreUI version and the newest document ibtool accepts, 17B55 from 17C52 in the same three, and 17B100 from 17B55 only in its version strings and the newest document ibtool accepts, listed below): every `assetutil --info` rendition field of the Parity catalog and of a single-size AppIcon catalog,
the app-icon partial Info.plist, the app-icon PNG bytes, copypng's behaviour on all 40 case/option combinations,
the `Info.plist` and `UIViewController-*.nib` of every storyboard in the corpus, and the `actool`/`ibtool`
log output (empty bar the result paths).

Different (one row per profile field below): the version numbers, the CAR header strings and CoreUI version, three nib
encodings (a key, a default colour, a double precision), font-dictionary uniquing in two cases, and the highest
document capability ibtool accepts.

Runtime note (27B52): ibtool 27.2 writes an SF Symbol image view (`catalog="system"`) in the symbol form (0.0 x 0.0,
`UISystemSymbolResourceName` = the name) only when the iOS 27.2 simulator runtime is installed. With only the iOS 27.0
runtime installed (the state in which 27A9275 was measured) it wrote the asset form (1.0 x 1.0, no symbol name) for the
same symbols: 6 `.nib` files in 3 corpus cases (`image-symbol-grid`, 4 flag sets; `image-uniquing`;
`image-system-symbol-no-resource`) differed from the 27A9275 goldens. After `xcodebuild -downloadPlatform iOS` under the
Xcode 27.2 `DEVELOPER_DIR` the same storyboards compiled to the 27A9275 bytes, so the symbol set comes from the installed
runtime, not from ibtool (an inference from this one before/after; the cause was not looked into further). Record
goldens with the runtime of the Xcode's own version installed.

Task 3 note: a stale storyboard `toolsVersion` is not what ibtool refuses. The limit that makes an older ibtool refuse a
newer document is the capability `minToolsVersion` against the Xcode's `short-bundle-version` (27.0 and 26.2 above). A plain
`toolsVersion="25098"` document compiles under 26.2.

## Concerns recorded while measuring

- `Tests/IBCorpus/golden/<build>/` holds the compiled `.storyboardc` files (nibs and `Info.plist`) that ibtool wrote. That is
  Apple tool output, not only `assetutil`/`plutil` fields. The 27A266a set was committed that way before this task, and
  the 17C52 set follows the same form so the two can be compared; this is recorded as a concern, not a policy change.
- The corpus storyboards, the Parity catalog and the copypng PNGs are xless-made.
